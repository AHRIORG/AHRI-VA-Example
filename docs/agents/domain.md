# Domain documentation

This repository uses a single-context layout: the domain glossary is [CONTEXT.md](../../CONTEXT.md) at the root and architectural decisions are in `docs/adr/`.

Before exploring domain behaviour or writing a spec, read the glossary and relevant ADRs. Use glossary terminology and respect accepted decisions; surface any proposed conflict explicitly.

For the replication benchmark, read the [accepted design interview](../design-interview.md) for the protocol and the [input-specification review](../input-spec-review.md) for documentary limits and unresolved private-input assumptions.

If a referenced domain document is missing, continue without inventing its contents. Actual-input facts remain unresolved until the user's private review.
